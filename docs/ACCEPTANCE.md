# ERPNext v16 acceptance checks

Run on a disposable site with a backup. These checks have not been executed in the authoring environment.

1. Install and migrate twice. Confirm six DocTypes (including the child table), two Script Reports and custom fields on both invoice/header and item DocTypes exist without duplicates. Confirm the Apply Oman VAT button appears on draft Sales and Purchase Invoices. Confirm connector automatic options are off.
2. Create an Oman/OMR company, fill Tax ID, set OMR precision to 3, and configure three dedicated accounts. Enable VAT with an activation date before the test transactions. Confirm a non-Oman or non-OMR company, group accounts, or accounts from another company are rejected.
3. Create standard sales 100 + VAT 5. Confirm receivable 105 and Output VAT credit 5. Repeat gross-inclusive 105 and foreign currency equivalent 100 OMR; confirm base VAT remains 5. Test line and invoice discounts.
4. Create a mixed Sales Invoice with standard 100, zero 50, exempt 25, export 200 and out-of-scope 30. Confirm VAT 5, receivable 410, working values in 1a/1b/1c/3a and out-of-scope exclusion. Use repeated item codes and verify row-level identities. Attempt missing taxes, wrong templates/rates, duplicated VAT rows, unrelated charges and Valuation-only purchase VAT; confirm submission fails.
5. Create standard purchase 100 with 50% recovery. Confirm supplier payable 105, Input VAT debit 2.5, Blocked VAT Expense debit 2.5. Repeat recovery 0% and 100%. Confirm no rounding drift with multiple low-value items.
6. Create reverse charge purchase 100 with 50% recovery. Confirm supplier payable 100, input debit 2.5, expense debit 2.5, output credit 5. Repeat capital asset flag; eligible input should move to box 6c.
7. Make linked sales and purchase returns. Confirm native negative amounts, 5b/6d negative VAT adjustments, and original treatment/recovery requirements. Confirm unlinked returns fail.
8. Use the imports and adjustments in ACCOUNTING.md. Confirm mismatched dates, company, JE docstatus or VAT balances fail. Confirm one JE cannot support two submitted VAT entries and cannot be cancelled while a submitted VAT entry links to it.
9. Verify Summary and Register against the ledger. Confirm zero and exempt purchase values, exports and capital asset input are correctly separated. Confirm draft and cancelled sources are excluded. Confirm an old submitted invoice without a VAT snapshot stops return generation.
10. Create a past-period VAT Return. Confirm client changes to totals, boxes and snapshot are overwritten on save/submit. Submit it and verify overlapping returns, backdated invoices, and source cancellations in the period fail. Cancel the internal return and confirm the period unlocks. Confirm future/current-period submission fails.
11. With two browser sessions, race source submission/cancellation against return submission and race overlapping return submissions. Only a consistent outcome should commit. Test JE cancellation against VAT Entry submission. Verify this on the actual database engine.
12. With two companies, verify company restrictions for forms, reports, API methods and return generation. A user without Accounts Manager must not get company-wide VAT reports or create tax entries/returns. Invoice users with create rights may request tax rows only for permitted companies.
13. Verify attachment permissions, normal report exports and immutable source snapshots. After manual portal filing, enter filing reference and receipt on the submitted return; confirm totals cannot be changed.
14. Test stock/inventory and fixed asset posting behavior with blocked expense tax, POS exclusion, and interactions with installed custom apps. Reconcile closing VAT balances and filing box values before release approval.
15. On one Purchase Invoice mix standard 100 at 50% recovery, reverse charge 200 at 100% recovery, exempt 50 and capital asset 1,000 at 100% recovery. Confirm input VAT 62.5, reverse-charge output 10 and blocked expense 2.5. Verify 6a base 350, 6c input 50 and RCM box 2b base 200/output 10. Test explicit 0% row overrides and inherited header defaults.
16. Test master Item/Item Group template rules, discounts, inclusive prices, foreign currency and low-value mixed lines. Confirm native item VAT totals reconcile exactly with tax-account totals; zero-rate rows must carry no VAT.
17. Confirm mixed credit-note rows preserve original classification. Repeated item codes must reference the correct original item row, not merely match item code.
18. Configure an actual provider sandbox adapter. Verify no direct network call happens during source save/submit. Two concurrent queue actions and duplicate worker jobs must not produce duplicate filings/invoices. Confirm source failure rolls back creation of its outbox record.
19. Force timeout after the provider receives a request. Confirm Unknown, no blind retry, and successful read-only lookup using idempotency key. Kill the worker during Sending and confirm reconciliation after expiry. Validate final receipts against the correct taxpayer/environment/document.
20. Check connector permissions and password-field access. Reject unregistered adapters, wrong capabilities and non-production-ready adapters in Production. A connector/environment change must not redirect an already frozen submission.
21. For Fawtara, validate actual PINT OM XML and TDD using the applicable published resources and provider sandbox. Check all required metadata, foreign currency/rounding, zero/exempt reasons, UUID/hash/QR rules, credit-note references and archive evidence. A provider job acknowledgement must remain Pending until Authority acceptance is verified.
22. Confirm Accepted requires both Authority and receipt references, that production submissions block inappropriate local cancellation, and that only Queued records can be cancelled before sending. Confirm sandbox operations do not appear as actual filings.

Release acceptance requires successful installation, real ledger checks, period-lock concurrency tests and review of the live tax portal mapping. Record exact Frappe/ERPNext versions and database engine in your deployment notes.
